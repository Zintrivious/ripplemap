ripplemap GitHub ↗

See which repos break when you change one.

You're about to change a shared base image, Terraform module, CI workflow or library. Who uses it? Who's still on an old version? ripplemap reads the files your repos already have and answers in seconds. There's nothing to configure and nothing to install on a server.

Why you'd want this

  • Before a breaking change: know exactly which repos to update, and who to tell.
  • On every pull request: a GitHub Action comments with the repos the change may affect, and flags the ones that will pick it up the moment it merges.
  • Version drift: see which repos are still on an old base image, module or library version.
  • Unpinned references: find repos on latest or @main that change underneath you.

Try it on your org

Needs Node.js 22 or newer. If you're logged in with the GitHub CLI (gh auth login), that's all the setup there is:

npx ripplemap scan --org your-org
npx ripplemap report --open

On Azure DevOps? Use --azure-org your-org with AZURE_DEVOPS_TOKEN set to a personal access token with Code (read) scope.

Not using gh? Set GITHUB_TOKEN to any token instead. Without one, GitHub only allows enough requests for about 50 repos an hour. Private repos work too, and nothing leaves your machine.

Or get a comment on every pull request

name: ripplemap
on: pull_request_target
permissions:
  contents: read
  pull-requests: write
jobs:
  impact:
    runs-on: ubuntu-latest
    steps:
      - uses: Zintrivious/ripplemap@v0

Save it as .github/workflows/ripplemap.yml in a repo others depend on. It reads files through the API and never runs the pull request's code.

What it reads

Dockerfiles, Terraform modules, GitHub Actions workflows, Azure Pipelines templates, Kubernetes manifests, Helm charts, Docker Compose, package.json, go.mod, and Python's pyproject.toml and requirements.txt.

Free and open source (MIT). Star it on GitHub if it's useful, and open an issue if it misreads your files.
